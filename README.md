# Firewall-UI

Веб-панель для управления файрволлом Linux. Показывает занятые порты и процессы, позволяет настраивать правила доступа.

[Релизы](https://github.com/SawaMEN/Firewall-UI/releases) · [Сообщить об ошибке](https://github.com/SawaMEN/Firewall-UI/issues)

## Возможности

- Управление UFW, firewalld, nftables и iptables.
- Активные TCP/UDP-порты, адреса, процессы и PID; опубликованные порты Docker/Podman.
- Группировка портов по процессам с раскрывающимися диапазонами: `9000-9002`. Пропуски остаются отдельными строками.
- Открытие и закрытие портов, правила для диапазонов, IP и подсетей.
- История изменений, резервные копии и автоматический откат при потере связи во время изменения правил.
- Доступ по домену или IP с HTTPS, смена логина и пароля в настройках.
- Три темы: **киберпанк** — первая и стандартная, светлая и тёмная. Выбранная тема сохраняется в браузере.

## Установка

Нужен Linux с работающим systemd, архитектура **amd64** или **arm64** и права root. Для установки готового релиза Go и Node.js не требуются.

Выполните от root:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/SawaMEN/Firewall-UI/main/install.sh)
```

Меню на русском: показывает установленные варианты, состояние и адрес подключения. После действий возвращается в меню. Ответы на вопросы подтверждения — **`y/n`**, выход и возврат назад — **`0`**.

При выборе обычной установки скрипт проверит файрволл и установит UFW, если поддерживаемый файрволл не найден. Существующие правила сохраняются; UFW автоматически не включается.

При установке задайте логин, пароль, порт и способ доступа:

| Режим | Подключение |
| --- | --- |
| Локальный | Только с сервера или через SSH-туннель. По умолчанию `http://127.0.0.1:8088` |
| Домен | `https://panel.example.com:порт` |
| IP | `https://IP:порт` |

Для внешнего доступа можно выбрать готовый сертификат, Let’s Encrypt или самоподписанный сертификат. Последний вызовет предупреждение браузера. Выпуск и продление через Let’s Encrypt требуют свободного TCP-порта 80, доступного из интернета; для домена нужна DNS-запись на сервер, для IP — Certbot 5.3 или новее. Порт панели также должен быть разрешён в файрволле хостинга.

Пароль может быть любой непустой длины. Рекомендуется длинный уникальный пароль. После установки терминал покажет адрес панели.

Для локального режима откройте SSH-туннель на своём компьютере:

```bash
ssh -L 8088:127.0.0.1:8088 user@server
```

Затем перейдите в браузере на `http://127.0.0.1:8088`.

## Docker Compose

Версию через Docker Compose можно установить той же командой установщика: выберите **1) Установить / обновить** и затем **2) Docker Compose**. В выборе варианта **1** означает обычную установку, **0** возвращает в главное меню. Мастер проверит Docker Engine и Docker Compose, предложит логин, пароль, порт и прямой доступ по IP либо локальный доступ через SSH-туннель.

Контейнер запускается и обслуживается командами `docker compose`; используется файл `compose.yaml` с сетью хоста. Для установки без меню используйте параметр `--compose`.

Пункт **2** открывает настройки адреса, порта, логина и пароля; **3** сбрасывает пароль с сохранением логина. Пункт **4** полностью удаляет обычную установку и Docker Compose вместе с их данными. Вверху меню показано, что установлено и запущено. Команды `sudo firewall-ui` и `sudo firewall-ui-docker` открывают одно меню, сохранённое на сервере. Учётные данные и параметры установщика хранятся в `/opt/firewall-ui-docker` с доступом только для root. HTTPS настраивается в самой панели.

Нужен Docker Engine с Compose на Linux. Контейнер использует сеть и процессы хоста и запускается с расширенными правами для управления файрволлом.

Готовые образы для amd64 и arm64 собираются и проверяются на GitHub, затем публикуются в релизах. Установщик скачивает образ нужной архитектуры, проверяет SHA-256 и загружает его в Docker. Исходники и средства сборки на сервере не нужны.

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/SawaMEN/Firewall-UI/main/install.sh) --compose
```

Логин по умолчанию — `admin`. Панель доступна на `http://127.0.0.1:8088`; для подключения с другого компьютера используйте SSH-туннель выше. Доступ по IP/домену, порт и HTTPS настраиваются в панели. Сертификаты разместите в её томе `/etc/firewall-ui`.

Настройки, изменённые логин и пароль, история и резервные копии сохраняются в Docker-томах. Контейнер управляет nftables/iptables хоста. При конфликтующих входящих правилах UFW/firewalld включение блокируется; для управления ими используйте обычную установку.

Для обновления повторите установку через пункт **1 → 2**. Управление: `sudo firewall-ui-docker`; пункт **7** запускает, останавливает и перезапускает панель, **8** показывает диагностику. Полное удаление обоих вариантов — пункт **4** основного установщика.

При удалении снимаются собственные правила панели и её запрет пинга, удаляются контейнеры и тома. Чужие правила файрволла и Docker остаются.

## Управление на сервере

Команда `sudo firewall-ui` открывает общее меню. В нём есть настройки, последние 100 строк журнала, управление службой и диагностика. Полное удаление требует подтверждения `y`; Enter отменяет удаление. Основные действия доступны отдельно:

| Команда | Действие |
| --- | --- |
| `sudo firewall-ui status` | Состояние службы |
| `sudo firewall-ui start` / `stop` / `restart` | Запуск, остановка, перезапуск |
| `sudo firewall-ui logs` | Журнал службы |
| `sudo firewall-ui update` | Обновление с проверкой SHA-256 |
| `sudo firewall-ui rollback` | Возврат предыдущего бинарника |
| `sudo firewall-ui credentials` | Изменение логина и пароля |
| `sudo firewall-ui reset-password` | Сброс пароля с сохранением логина |
| `sudo firewall-ui uninstall --purge` | Полное удаление |

Логин и пароль также меняются в веб-настройках. Для изменения домена, IP и сертификата повторно запустите команду установки и выберите настройку доступа. Сброс пароля и полное удаление доступны в том же меню.

Полное удаление убирает панель, её данные, сертификаты в `/etc/firewall-ui` и собственные правила. Системный файрволл, чужие правила и сертификаты из внешних каталогов сохраняются. `sudo firewall-ui uninstall` позволяет сохранить настройки и данные.

## Настройки и файлы

В панели доступны параметры HTTPS и порта, разрешённые IP/подсети, резервные копии, история и канал обновлений: **Stable** или **Dev**.

| Путь | Содержимое |
| --- | --- |
| `/etc/firewall-ui/config.json` | Конфигурация панели |
| `/etc/firewall-ui/environment` | Учётные данные |
| `/var/lib/firewall-ui` | Состояние, история и резервные копии |
| `/usr/local/firewall-ui/firewall-ui` | Бинарник |

При включённом HTTPS используйте `https://` и выбранный порт. Обычные HTTP-ссылки на этот порт перенаправляются на HTTPS; учётные данные по HTTP не принимаются. Некорректные TLS-пакеты от внешних клиентов отклоняются и могут появляться в журнале.

Если панель не открывается, проверьте `sudo firewall-ui status` и `sudo firewall-ui logs`, выбранный режим доступа и разрешение порта у хостинга.
