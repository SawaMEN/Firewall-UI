# Аудит nftables — hotfix 1.4.1

Консолидированное состояние после 1.4.0. Ниже сохранены результаты двух
проверок, вошедших в единый hotfix, и их границы.

## Первая проверка

База проверки: 1.4.1 (`eb22b457d29a318b6f399ea1798f59374f35d0ac`).
Проверены native backend, генерация INPUT, дополнительная таблица INPUT/FORWARD,
состояние и проверки ядра, кеши, закрытие/открытие портов, автосверка, резервные
копии, восстановление, переключение и очистка, диагностика и счётчики.

### Подтверждённые дефекты и исправления

тестовые комбинации IPv4/IPv6, TCP/UDP не считаются дополнительными дефектами.

### Проверки

- Go unit-тесты с `-race`, `go vet`, форматирование.
- Frontend unit-тесты, TypeScript/production build и браузерные регрессии CI.
- Обязательный job `nftables kernel integration`: тестовый бинарник запускается
  в отдельном root network namespace и отказывается работать в исходном namespace.
- Реальные TCP/UDP IPv4/IPv6 INPUT: close, повторный close, reopen, восстановление
  опустевшей цепочки, отказ при чужом hook без удаления текущей защиты, disable и restore.
- Два дополнительных namespace с veth: клиент → DNAT → сервер. Порт хоста 19332
  перенаправлен на 19333; проверяются IPv4/IPv6, TCP/UDP, ручные исключения и DROP.
- Отдельные INPUT-проверки замороженных сервисов и расширенных правил:
  CIDR, интерфейс, диапазон, приоритет deny над allow и удаление правил.
- Включение/восстановление таблиц после `flags dormant` проверяется в реальном ядре.
- 42 комбинации advanced-выражений проходят настоящий `nft --check`.
- Первый прогон стенда выявил необходимость ожидания IPv6 neighbor discovery
  и неверное оформление тестового однострочного nft-блока. Это ошибки стенда,
  они не включены в список дефектов приложения.

### Границы результата

Проверка не является доказательством отсутствия любых других ошибок. Доступа
к рабочему серверу пользователя и его сторонним таблицам/маршрутизации нет.
Пакетные проверки выполняются на Linux runner CI; смешанные реальные установки
UFW/firewalld, правила хостинг-провайдера и все версии ядер этим не исчерпываются.

Native backend управляет только зарезервированными owned-таблицами. Сторонние
INPUT hooks по-прежнему отклоняются; произвольные внешние nftables-правила не
удаляются и не импортируются в управляемую политику. Параллельный внешний
администратор может изменить ruleset после любой проверки — следующая сверка
обнаруживает drift. Общие advanced-правила применяются после системных
исключений established/loopback/ICMP и защищённого доступа; индивидуальное
«закрыть порт» дополнительно блокирует INPUT/FORWARD до established.

Семантика `dormant` сверена с [официальным руководством nftables](https://netfilter.org/projects/nftables/manpage.html): при этом флаге base chains снимаются с hooks.

На runner с nft 1.0.9 обнаружено, что при dormant-таблице JSON может содержать
`"flags": "firewall_ui_containers"` (имя таблицы вместо флага). Поддержаны строка
и массив флагов; неизвестные значения не принимаются как доказательство
активной фильтрации. Это подтверждено реальным снимком ядра в CI, а не только
синтетическим JSON.

### Проверки и границы

- Go unit/regression с `-race`, `go vet`, форматирование.
- Frontend: 23 теста, TypeScript и production build; браузерные регрессии CI.
- Изолированные kernel-тесты: TCP/UDP IPv4/IPv6 INPUT и DNAT/FORWARD,
  закрытие/повтор/открытие, dormant, восстановление, CIDR/интерфейсы/диапазоны/приоритеты,
  42 синтаксические комбинации advanced.
- Добавлены kernel-проверки: сохранённый OFF с оставшейся native-таблицей,
  диагностика защищённой DNAT-панели при broad deny, статус и unknown после flush FORWARD.
- Unit-проверки отклоняют пустую/нечитаемую/некорректную таблицу после успешной
  команды, пропавший закрытый порт, перестановку правил, изменённый verdict и no-op delete.

Это проверка реализации и воспроизводимых сценариев, а не доказательство
отсутствия всех возможных ошибок. Исходный рабочий сервер пользователя не
изменялся. Проверка marked rules подтверждает наличие, порядок и verdict;
она не является универсальным доказательством эквивалентности произвольных
nftables-выражений. Полный отпечаток обнаруживает последующее изменение
снимка, но внешний процесс всё равно может изменить правила после проверки.
Сторонние INPUT hooks не удаляются; ограничения смешанных установок и версий
ядра из отчёта 1.4.2 сохраняются.


## Ручные правила TCP + UDP

При повторном открытии существующие ручные записи и их описания сохраняются.
Создаётся только отсутствующая запись протокола; закрытие не удаляет ручную
пару. Добавлены проверки сохранения на диск и реальные kernel-регрессии
IPv4/IPv6 TCP/UDP DNAT close/reopen.
