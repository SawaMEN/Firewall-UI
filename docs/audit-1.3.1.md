# Проверка 1.3.1

Подтверждены и исправлены 25 проблем. Число 200 не подтверждено: отдельные тестовые варианты и изменения строк кода не считаются отдельными ошибками. Проверка не гарантирует отсутствие других дефектов.

| № | Проблема | Исправление |
| --- | --- | --- |
| 1 | Незавершённый запрос входа блокировал настройки и другие входы | Чтение тела выполняется до захвата общего замка |
| 2 | Таблица попыток входа превышала лимит и блокировала уже известные IP | Точный предел, известный клиент может завершить вход |
| 3 | Origin с другим протоколом проходил проверку | Проверяются схема, адрес и отсутствие дополнительных компонентов |
| 4 | Пустые CIDR незаметно отключали ограничение доступа | Исходные значения проверяются до нормализации во всех путях сохранения |
| 5 | JSON null в файле состояния вызывал панику при записи | Возвращается ошибка без перезаписи файла |
| 6 | JSON null вместо меток правил вызывал панику при редактировании | Создаётся пустая карта меток |
| 7 | Подписка после остановки мониторинга оставалась открытой | Новая подписка сразу закрывается |
| 8 | Docker-диапазоны опубликованных портов пропускались | Диапазоны разбираются с точным соответствием портов |
| 9 | Принимались некорректные целевые порты контейнера | Проверяются обе границы и длины диапазонов |
| 10 | Порт на конкретном внешнем IP считался непубличным | Любая привязка вне loopback отмечается как доступная через сеть |
| 11 | Большая строка Docker ps обрывала чтение списка | Увеличен допустимый размер строки |
| 12 | Повторный ID расширенного правила приводил к неоднозначному удалению | Дубликаты запрещены при добавлении и восстановлении |
| 13 | Произвольные ID могли ломать комментарии; некоторые допустимые ID не удалялись | Общая проверка ID для создания и очистки |
| 14 | Резервная копия сохраняла некорректные ручные правила | Порты, протоколы и дубликаты проверяются до изменения состояния |
| 15 | Импорт мог подменить зарезервированное правило закрытия порта | Проверяется точная семантика зарезервированных ID |
| 16 | Проверка резервной копии изменяла переданные вызывающим кодом данные | Восстановление работает с копиями массивов |
| 17 | nftables получал некорректное правило TCP/UDP без номера порта | Используется meta l4proto |
| 18 | firewalld игнорировал сохранённый приоритет правила | Приоритет включён в rich rule; удаляются и старые варианты без него |
| 19 | Поиск UFW по части комментария выбирал чужую строку | Комментарии сравниваются полностью |
| 20 | Длинная метка могла обрезаться внутри символа UTF-8 | Используется единая обрезка по целым символам |
| 21 | Обновление принимало второй JSON или мусор после манифеста | Требуется один завершённый JSON-объект |
| 22 | Ограничение размера манифеста не обнаруживало лишние данные | Проверяется фактический размер с контрольным дополнительным байтом |
| 23 | Интерфейс объединял правила с различными метками и состояниями | Полная семантика включена в ключ группировки |
| 24 | Снимок, изменение и регистрация отката могли перемежаться между запросами | Операции и экспорт резервной копии выполняются последовательно |
| 25 | Старый таймер отката мог отменить новое изменение | Разрешена одна ожидающая или выполняющаяся транзакция |

Из релизов исключён дублирующий install.sh. Файл остаётся в репозитории и доступен по прежней команде установки. update.json и docker-update.json сохранены: текущие установщики и автообновление используют их ссылки и SHA-256.

Регрессии проверяются в Go-тестах конфигурации, сервера, сервиса, отката и обновления; группировка — в тестах интерфейса. CI также проверяет установку, удаление, авторизацию в браузере и Docker с реальным файрволлом на amd64/arm64.
