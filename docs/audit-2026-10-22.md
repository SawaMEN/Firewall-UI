# Firewall-UI: targeted correctness/security audit (22 October 2026)

Base: main at `3b9902251be9e9ebdf40a8b8b6eb969cb43f759a`. Work branch: `audit/hardening-2026-10-22`, PR #11.

## Verified defects addressed

Only issues with an identifiable code path and a deterministic corrective change are counted. **This pass does not establish 200 independent bugs.** Existing fixed issues from prior audit reports are not counted again.

| # | Confirmed problem | Fix |
|---|---|---|
| 1 | Restoring a backup with `managedEnabled=false` deleted panel-owned rules but left the whole UFW/firewalld service running, contrary to the current system-firewall switch semantics. | Disable the real service and verify state; preserve administrator-owned rules. |
| 2 | Backup export saved the old preference instead of the live UFW/firewalld state, creating a risk of an unexpected host-wide shutdown during rollback. | Snapshot live system service state. |
| 3 | Re-restoring a UFW backup replayed advanced rules blindly, potentially duplicating already-present rules. | Reconcile saved owned advanced UFW rules. |
| 4 | A manual rule update wrote the rules and labels in separate state-file transactions. Failure between writes could leave mismatched labels. | Atomically update both keys. |
| 5 | Failed host synchronization after adding/deleting a manual rule left the unsuccessful change in persistent state. | Restore previous rules/labels and attempt live recovery with independent timeout. |
| 6 | Auto-sync enablement saved the enabled preference before backend detection or rule application, retaining a false setting after failure. | Preflight backend and roll back preference/live rules on failure. |
| 7 | Changing the selected firewalld zone trusted the saved disabled preference even when firewalld had been started outside the panel. | Check live backend state and reject zone changes while active. |
| 8 | UFW port verification ignored earlier `ALLOW` rules covering a port range. | Match exact ports, UDP/TCP ranges, and first applicable rule. |
| 9 | UFW verification ignored earlier wildcard `ALLOW Anywhere` rules. | Consider all-ports UFW entries in precedence analysis. |
| 10 | A source-restricted `DENY` could be misreported as blocking a port globally. | Skip restricted deny rules when verifying a global close. |
| 11 | A source-restricted `ALLOW` preceding a global deny could be overlooked by the effective-state check. | Treat preceding restricted allowances as potential exposure. |
| 12 | IPv6-only denial could satisfy a check intended to verify IPv4 and IPv6. | Require IPv4 deny independently; continue independent IPv6 check. |
| 13 | Short-form `ufw allow 1332/tcp from ...` rules were interpreted as unrestricted global allows. | Validate interface/source/destination restrictions before accepting short-form rules. |
| 14 | The nftables FORWARD synchronization cache refreshed its own timestamp without checking live rules, so an externally removed table rule was never restored. | Reapply only the owned table after the cache interval, preserving unrelated nftables policy. Note: its counters reset on reapply. |

## Regression verification

Added tests covering source/range/wildcard UFW rule precedence, backup restoration of disabled UFW, backup export of live UFW state, manual rule and auto-sync rollback on synchronization error, and expired container FORWARD cache. All host control tests use temporary mocked executables and sysctl files; they do not touch the CI runner firewall.

These tests supplement, not replace, the existing CI suites for Go, the frontend, Linux distributions, Docker and browser behavior. Network reachability must ultimately be checked from an external host.

## Scope limitations

No direct access to the user's installed server, hardware, or real production UFW rule list. Some combinations involving the UFW default policy, extra iptables/nftables administrator chains, Docker forwarding, and IPv6 require integration tests on a real Linux host. This report lists neither hypothetical defects nor copies of the same underlying bug as additional items to reach an arbitrary total.
